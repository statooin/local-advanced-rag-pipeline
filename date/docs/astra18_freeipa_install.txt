Сборник практических заданий для курса «AL-1804. Сетевое администрирование ОС Astra Linux Special Edition 1.8»

Требования:
• Компьютер со следующими характеристиками:
• процессор архитектуры AMD64 (x86_64) не менее 8 ядер;
• RAM не менее 32 Гб;
• NVME или SATA SSD-диски, не менее 300 Гб свободного места.
• ОС GNU/Linux или Windows 10 (или более новые версии).
• VirtualBox 6.1.

Материалы:
• Эталонная виртуальная машина template_1804_1_6:
• процессор — 1;

• RAM —2 Гб;
• диск — 30 Гб;
• сетевой адаптер —тип подключения NAT;
• ОС — Astra Linux Special Edition 1.8.1.6 (максимальный уровень защищенности) с установленными дополнениями VirtualBox для гостевых ОС.

Дополнительная информация:
• Настройки эталонной виртуальной машины предполагают, что репозитории Astra Linux 1.8.1.6 доступны через сеть Интернет.
• В учебном центре репозитории могут располагаться на внутренних ресурсах УЦ. В этом случае в эталонную ВМ должны быть внесены соответствующие изменения.

МОДУЛЬ 1
ОСНОВЫ СЕТЕЙ TCP/IP. НАСТРОЙКА И ДИАГНОСТИКА СЕТИ

Модуль 1. Основы сетей TCP/IP. Настройка и диагностика сети

Описание практического задания
• Настройка сетевых интерфейсов в виртуальной машине (ВМ) infra с помощью NetworkManager.
• Настройка сетевого интерфейса в ВМ server1 с помощью команд ifup/ifdown.
• Агрегирование (объединение) Ethernet-интерфейсов на ВМ infra.

Схема сети

Настройка ВМ infra
Задание: настроить ВМ infra, первоначально изменив имя хоста (infra), а затем настроить сетевое подключение, соответствующее интерфейсу eth0, с использованием NetworkManager; далее внести информацию об имени и адресе хоста в файл /etc/hosts и включить внутреннюю маршрутизацию.

2 Клонировать ВМ template_1804_1_6 и назвать новую ВМ infra.
3 Не запуская ВМ infra, добавить два сетевых интерфейса (всего три). Один (первый) интерфейс — NAT, два других — внутренняя сеть.
4 Запустить ВМ infra.
5 Сменить имя хоста на infra с помощью команды hostnamectl.
sudo hostnamectl set-hostname infra
6 Создать запись для infra в файле /etc/hosts:
127.0.0.1 localhost

10.0.1.254 infra
7 Изменить имена соединений в NetworkManager на net1, net2, net3 так, чтобы названия сетевых соединений для первого (eth0), второго (eth1) и третьего (eth2) интерфейса имели вид net1, net2, net3.
nmcli con sh

nmcli con mod <старое имя> con-name <новое имя соединения>
8 Проверить, получил ли внешний интерфейс (NAT) сетевые настройки по DHCP.
ip a sh eth0

9 Настроить соединение net2: IP-адрес 10.0.1.254/24. Проверить, чтобы настройка сетевого соединения была произведена успешно.
nmcli con mod net2 ipv4.addresses 10.0.1.254/24 ipv4.method manual
nmcli con up net2
ip a s eth1
10 Включить внутреннюю маршрутизацию.

sudo sysctl -w net.ipv4.ip_forward=1
11 Настроить автоматическое включение маршрутизации при загрузке системы путем внесения изменений в файл /etc/sysctl.conf.
net.ipv4.ip_forward=1

Настройка ВМ server1
Задание: настроить ВМ server1, первоначально изменив имя хоста (server1), затем настроить сетевой интерфейс eth0 с использованием файла interfaces и внести информацию об имени и адресе хоста в файл /etc/hosts.
1 Клонировать ВМ template_1804_1_6 и назвать новую ВМ server1.
2 Запустить ВМ.
3 Сменить имя хоста на server1 командой hostnamectl.
sudo hostnamectl set-hostname server1
4 Добавить в файл /etc/hosts запись о server1:
127.0.0.1 localhost

10.0.1.1 server1
5 Остановить и запретить запуск NetworkManager.
sudo systemctl stop NetworkManager

sudo systemctl mask NetworkManager
6 Настроить сетевой интерфейс eth0 в файле /etc/network/interfaces:
• IP-адрес 10.0.1.1/24;
• шлюз 10.0.1.254.
auto eth0

iface eth0 inet static

address 10.0.1.1/24

gateway 10.0.1.254
7 Перезапустить службу и проверить настройки сетевого интерфейса и доступность шлюза.
sudo systemctl restart networking
sudo ifdown eth0
sudo ifup eth0
ip a s eth0
ping 10.0.1.254

Настройка агрегации Ethernet-интерфейсов
Задание: настроить агрегацию сетевых интерфейсов eth1 и eth2 в режиме active backup на хосте infra с использованием NetworkManager, затем произвести сетевые настройки агрегированного интерфейса и с помощью утилиты tcpdump проверить работоспособность агрегированного сетевого интерфейса путем отключения/включения интерфейсов.
1 Настройка производится на ВМ infra.
2 Убрать настройки и отключить сетевое соединение net2.
nmcli con mod net2 ipv4.method auto

nmcli con down net2
3 Создать (добавить) логический ведущий (master) интерфейс типа bond с именем сетевого интерфейса bond0 с помощью NetworkManager.
nmcli con add type bond ifname bond0
4 Настроить Ethernet-интерфейсы eth1 и eth2 как подчиненные (slave) интерфейсы.
nmcli con add type ethernet ifname eth1 master bond0
nmcli con add type ethernet ifname eth2 master bond0
5 Определить название сетевого соединения типа bond.
nmcli con sh
6 Настроить статический адрес 10.0.1.254 на интерфейсе bond0.
nmcli con mod bond-bond0 ipv4.addr 10.0.1.254/24 \ ipv4.method manual
7 Активировать настройки bond0.
nmcli con up bond-bond0
8 Проверить, чтобы интерфейс bond0 был настроен и server1 доступен.
ip a s bond0
ping 10.0.1.1
9 Включить на интерфейсе bond0 режим активный — резервный.
nmcli con mod bond-bond0 bond.options mode=active-backup
10 Включить на интерфейсе bond0 режим переназначения MAC-адреса на активный интерфейс (параметр fail_over_mac).
nmcli con mod bond-bond0 +bond.options fail_over_mac=1
11 Активировать изменения на интерфейсе bond0 и проверить, чтобы режимы агрегирования были настроены верно.
nmcli con up bond-bond0

nmcli con sh bond-bond0 | grep bond
12 Установить tcpdump.
sudo apt install tcpdump
13 Запустить непрерывную проверку доступности хоста 10.0.1.1.
ping 10.0.1.1
14 Запустить еще два терминала, в которых осуществлять перехват ICMP сообщений на интерфейсах eth1 и eth2.
sudo tcpdump -i eth1 icmp
sudo tcpdump -i eth2 icmp
15 В VirtualBox отключить сетевую карту (Устройства → Сеть → Подключить сетевой адаптер 2), по которой передаются данные, и проверить, чтобы передача данных производилась по резервному каналу.
16 Снова включить сетевую карту (сетевой адаптер 2). Обратите внимание на работу утилиты tcpdump: как вы видите, все осталось без изменений и трафик по-прежнему идет по eth2. Чтобы вернуть все назад, необходимо временно отключить интерфейс eth2 (сетевой адаптер 3).

МОДУЛЬ 2
НАСТРОЙКА УДАЛЕННОГО ДОСТУПА ПО SSH

Модуль 2. Настройка удаленного доступа по SSH

Описание практического задания
• Настройка аутентификации по ключам при подключении по SSH с ВМ infra к ВМ server1, и наоборот.
• Создание и настройка ВМ server2.
• Настройка аутентификации по ключам при подключении по SSH с ВМ infra к ВМ server2, и наоборот.
• Переадресация портов с помощью SSH:
• динамическая переадресация и настройка утилиты apt;
• переадресация локального порта для доступа к сетевым службам.

Схема сети

Настройка аутентификации по ключам
Задание: на хосте infra настроить SSH-подключение по ключам к хосту server1; на хосте server1 настроить SSH-подключение по ключам к хосту infra; настроить ВМ server2:
• изменить имя хоста (server2);
• настроить сетевой интерфейс eth0 на server2 с использованием файла interfaces;
• на хосте infra настроить SSH подключение по ключам к хосту server2;
• на хосте server2 настроить SSH-подключение по ключам к хосту infra.
1 На server1 и infra проверить работоспособность службы ssh. При необходимости запустить службу ssh и добавить ее в автозагрузку.
sudo systemctl status ssh
sudo systemctl start ssh
sudo systemctl enable ssh
2 На ВМ infra настроить SSH-подключение по ключам RSA к хосту server1 под учетными записями sa. На ВМ infra выполнить следующие команды:
ssh-keygen -t rsa
ssh-copy-id sa@10.0.1.1
3 С ВМ infra зайти на ВМ server1 по ssh под пользователем sa, не вводя пароль. У вас должно получиться:
ssh sa@10.0.1.1
4 На ВМ server1 настроить SSH-подключение по ключам RSA к хосту infra под учетными записями sa. На ВМ server1 выполнить следующие команды:
ssh-keygen -t rsa
ssh-copy-id sa@10.0.1.254
5 С ВМ server1 зайти на ВМ infra по ssh под пользователем sa, не вводя пароль. У вас должно получиться:
ssh sa@10.0.1.254

6 Создать ВМ server2 путем клонирования ВМ template_1804_1_6.
7 В созданной ВМ server2 сменить имя хоста на server2.
sudo hostnamectl set-hostname server2
8 Добавить в файл /etc/hosts запись для server2:
127.0.0.1 localhost

10.0.1.2 server2
9 Остановить и запретить запуск NetworkManager.
sudo systemctl stop NetworkManager

sudo systemctl mask NetworkManager
10 Настроить сетевой интерфейс eth0 в файле /etc/network/interfaces:
• IP-адрес 10.0.1.2/24;
• шлюз 10.0.1.254.
auto eth0

iface eth0 inet static

address 10.0.1.2/24

gateway 10.0.1.254
11 Перезапустить службу networking. Проверить настройки и доступность шлюза.
sudo systemctl restart networking
ip a s eth0
ping 10.0.1.254
12 На server2 проверить работоспособность службы ssh. При необходимости запустить службу ssh и добавить ее в автозагрузку.
sudo systemctl status ssh
sudo systemctl start ssh
sudo systemctl enable ssh
13 На ВМ infra настроить SSH-подключение по ключам RSA к хосту server2 под учетными записями sa. Обратите внимание, что связку ключей на ВМ infra здесь не создаем, она уже была создана в пункте 4. На ВМ infra выполнить следующую команду:
ssh-copy-id sa@10.0.1.2
14 С ВМ infra зайти на ВМ server2 по ssh под пользователем sa, не вводя пароль. У вас должно получиться:
ssh sa@10.0.1.2
15 На ВМ server2 настроить SSH-подключение по ключам RSA к хосту infra под учетными записями sa. На ВМ server2 выполнить следующие команды:
ssh-keygen -t rsa
ssh-copy-id sa@10.0.1.254
16 С ВМ server2 зайти на ВМ infra по ssh под пользователем sa, не вводя пароль. У вас должно получиться:
ssh sa@10.0.1.254

МОДУЛЬ 3
СЛУЖБА ДОМЕННЫХ ИМЕН DNS

Модуль 3. Служба доменных имен DNS

Описание практического задания
• Настройка ведущего DNS-сервера.
• Настройка подчиненного DNS-сервера.
• Настройка кеширующего сервера.
• Настройка клиентской части DNS.

Схема сети

Настройка ведущего сервера DNS для зон astra.test и 1.0.10.in-addr.arpa
Задание: на хосте server1 установить DNS-сервер bind9; настроить на хосте server1 ведущий (master) DNS-сервер для зон astra.test и 1.0.10.in-addr.arpa: в файле /etc/bind/named.conf.local создать описание для этих зон и создать файлы с зонной информацией; зонная информация должна включать записи типа SOA и NS (DNS-серверы — server1.astra.test и server2.astra.test), а также информацию о хостах infra, server1 и server2; для имени server1.astra.test требуется определить псевдоним www.astra.test.
1 В ВМ server1 установить bind9.
Примечание: следует использовать SOCKS-прокси.
sudo apt install bind9
2 В файле /etc/bind/named.conf.local описать зону astra.test, для которой server1 является ведущим сервером DNS.
zone "astra.test"{
type master;
file "master/astra.test";
};
3 В файле /etc/bind/named.conf.local описать зону 1.0.10.in-addr.arpa, для которой server1 является ведущим сервером DNS.
zone "1.0.10.in-addr.arpa"{
type master;
file "master/10.0.1";
};
4 Проверить правильность внесенных изменений в настройки сервера DNS.
sudo named-checkconf
5 Создать каталог /var/cache/bind/master. Назначить группу bind группой — владельцем созданного каталога и установить бит защиты sgid.
sudo mkdir /var/cache/bind/master
sudo chgrp bind /var/cache/bind/master
sudo chmod g+s /var/cache/bind/master
6 Создать файл astra.test в каталоге /var/cache/bind/master с ресурсными записями для зоны astra.test:
• SOA;
• NS (server1.astra.test и server2.astra.test);
• A — для server1.astra.test, server2.astra.test, infra.astra.test (внутренний интерфейс);
• CNAME www server1. →

$TTL 1h
@ IN SOA server1.astra.test. dnsmaster.astra.test. (
2022032201 ; задать текущие значения yyyymmddnn
10800
3600
604800
86400 )
IN NS server1.astra.test.
IN NS server2.astra.test.
server1 IN A 10.0.1.1
server2 IN A 10.0.1.2
infra IN A 10.0.1.254
www IN CNAME server1
7 Проверить правильность внесения зонной информации в файл astra.test.
sudo named-checkzone astra.test \
/var/cache/bind/master/astra.test
8 Создать файл 10.0.1 в каталоге /var/cache/bind/master с ресурсными записями для зоны 1.0.10.in-addr.arpa:
• SOA;
• NS (server1.astra.test и server2.astra.test);
• PTR (для адресов 10.0.1.1, 10.0.1.2, 10.0.1.254).
$TTL 1h
@ IN SOA server1.astra.test. dnsmaster.astra.test. (
2022032201 ; задать текущие значения yyyymmddnn
10800
3600
604800
86400 )
IN NS server1.astra.test.
IN NS server2.astra.test.
1 IN PTR server1.astra.test.
2 IN PTR server2.astra.test.
254 IN PTR infra.astra.test.
9 Проверить правильность внесения зонной информации в файл 10.0.1.
sudo named-checkzone 1.0.10.in-addr.arpa \
/var/cache/bind/master/10.0.1
10 Перезапустить сервер DNS и проверить, чтобы служба DNS работала.
sudo systemctl stop bind9
sudo systemctl start bind9
systemctl status bind9
11 Установить утилиту nslookup из пакета dnsutils.
sudo apt install dnsutils
12 Проверить разрешение имен DNS сервером, все должно получиться.
nslookup server1.astra.test 10.0.1.1

Настройка подчиненного сервера DNS для зон astra.test и 1.0.10.in-addr.arpa
Задание: на хосте server2 установить DNS-сервер bind9; настроить на хосте server2 подчиненный (slave) DNS-сервер для зон astra.test и 1.0.10.in-addr.arpa, для этого в файле /etc/bind/named.conf.local нужно создать описание для этих зон, указав в качестве ведущего DNS-сервера server1; убедиться, чтобы трансфер зонной информации прошел успешно.
1 В ВМ server2 установить bind9.
Примечание: использовать SOCKS-прокси и настроить работу apt через прокси.
sudo apt install bind9
2 Проверить, запущена ли служба bind9. Если служба не работает, то запустить.
systemctl status bind9
3 Создать каталог /var/cache/bind/slave. Назначить группу bind группой — владельцем созданного каталога и установить на каталог бит защиты sgid.
sudo mkdir /var/cache/bind/slave
sudo chgrp bind /var/cache/bind/slave
sudo chmod g+s /var/cache/bind/slave

4 Настроить server2 как подчиненный (slave) сервер для зоны astra.test. Для этого внести соответствующие изменения в файл /etc/bind/named.conf.local. Зонную информацию хранить в файле /var/cache/bind/slave/astra.test.
zone "astra.test" {
type slave;
file "slave/astra.test";
masters {10.0.1.1;};
};
5 Настроить server2 как подчиненный (slave) сервер для зоны 1.0.10.in-addr.arpa. Для этого внести соответствующие изменения в файл /etc/bind/named.conf.local. Зонную информацию хранить в файле /var/cache/bind/slave/10.0.1.
zone "1.0.10.in-addr.arpa" {
type slave;
file "slave/10.0.1";
masters {10.0.1.1;};
};
6 Проверить правильность внесенных изменений в настройки сервера DNS.
sudo named-checkconf
7 Перезапустить сервер DNS и проверить, чтобы служба DNS работала.
sudo systemctl stop bind9
sudo systemctl start bind9
systemctl status bind9

8 Проверить трансфер зон командой.
sudo journalctl -u bind9.service
sudo journalctl -u named.service
9 Установить утилиту nslookup из пакета dnsutils.
sudo apt install dnsutils

Настройка самоподписанных сертификатов ( опциональное задание)
Задание: создать самоподписанный сертификат для веб-сайта infra.astra.test; настроить веб-сайт infra.astra.test для работы с использованием протокола TLS (SSL).
1 Создать удостоверяющий центр — CA (Certification Authority):
sudo -i
cd /etc/apache2/
mkdir ssl
chmod 700 ssl
cd ssl
openssl genrsa -des3 -out my-ca.key
Примечание: обязательно задать пароль, иначе следующая команда не будет работать.
2 Создать сертификат для удостоверяющего центра:
openssl req -new -x509 -days 3650 -sha256 \
-key my-ca.key -out my-ca.crt
3 В конфигурационном файле /etc/ssl/openssl.cnf найти и раскомментировать строку:
req_extensions = v3_req

4 В секции [ v3_req ] после строк:
basicConstraints = CA:FALSE
keyUsage = nonRepudiation, digitalSignature,

keyEncipherment
следует добавить строку
subjectAltName = @alt_names
После нее создать новую секцию [ alt_names ]
5 В новую секцию [ alt_names ] добавить строки вида DNS.X = домен, указав домены, для которых выпускается сертификат, где X = 1, 2, 3 и т. д. Можно указать несколько доменов/поддоменов:
DNS.1 = infra.astra.test
DNS.2 = www.infra.astra.test
DNS.3 = *.infra.astra.test
6 Создать файл ключа для веб-сервера (размер ключа — 2048 бит):
openssl genrsa -des3 -out my-apache.key 2048

7 Удалить пароль из файла ключа веб-сервера:
openssl rsa -in my-apache.key -out new.my-apache.key
mv new.my-apache.key my-apache.key
8 Создать запрос на подпись сертификата Certificate Signature Request (csr) в удостоверяющем центр:
openssl req -new -key my-apache.key -out my-apache.csr
Примечание: здесь при заполнении анкеты, аналогичной анкете на шаге 2, нужно будет ввести пароль, заданный на шаге 1.
9 Подписать сертификат Apache в удостоверяющем центре:
openssl x509 -req -in my-apache.csr \ -out my-apache.crt -sha256 -CA my-ca.crt \ -CAkey my-ca.key -CAcreateserial -days 366
Примечание: здесь вновь нужно будет ввести пароль, заданный на шаге 1.

SSLCertificateFile /etc/apache2/ssl/my-apache.crt
SSLCertificateKeyFile /etc/apache2/ssl/my-apache.key
SSLCACertificateFile /etc/apache2/ssl/my-ca.crt
